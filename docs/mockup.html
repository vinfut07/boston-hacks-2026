Web + mobile mockups

Each P0 page from the PRD, drawn at desktop width (left) and phone width (right) with the style guide's own classes. It's one web app, but the phone version is designed for phones on its own terms (bottom sheets, swipe gestures, step-by-step flows) rather than being the desktop page shrunk down. Red boxes list what's mobile-specific and any backend it needs. The blue box lists what the page needs from the backend; red items aren't in the schema yet. The white box describes the layout at both sizes.

Sample content for layout only. Places are real; costs, times and ratings are placeholders.

Mobile-only patterns

  • Full-screen map with a bottom sheet you can drag up and down
  • One stop at a time: swipe the sheet left or right to move between stops
  • Large checkboxes (56 px rows) you can tap while walking
  • “Swipe to complete” so nobody finishes a quest by accident
  • Keep the screen awake (Wake Lock API) while a quest is active
  • Resume after closing the app: reload the in-progress quest_run on open
  • Location stays on the phone only. Nothing is stored.

Backend needs

  • quest_runs: start/resume (one in-progress run per user per quest), complete, abandon
  • checkpoint_completions keyed by run, toggled on click
  • Location stays in memory only, with no table (PRD privacy rule)
  • MBTA V3: nearest stop + predictions for the next leg (client fetch; an API key raises rate limits)
  • External directions fallback. Never draw straight lines as routes.

Desktop layout

  • Focused mode: slim header with Exit, no main nav
  • Split view: map fills the left, a 420 px progress + checklist panel sits on the right

Mobile-only patterns

  • Four steps instead of one long form: Basics → Stops → Checkpoints → Review & publish
  • Place search fills the whole screen with big result rows. Tap + to add a stop.
  • Hold and drag to reorder stops; swipe left to delete one

  • Saving a draft every step means writing status='draft' early and updating it, so Create must also support updating a draft

Backend needs

  • Insert sidequest + stops (+ checkpoints) together. Ideally one RPC so a half-saved quest can't happen.

  • Draft vs. publish = status. Reordering uses the deferrable stop_order unique.
  • Cover image: URL for now. A Storage bucket only if we allow uploads.

Desktop layout
